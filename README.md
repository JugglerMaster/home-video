# home-video

A home video library: a web server that collects, indexes, and streams videos
from local folders and YouTube, running as a single Docker container.

See [SPEC.md](SPEC.md) for the full specification and
[PLAN.md](PLAN.md) for the phased build plan.

## Stack

- Rust (Axum), single crate, one binary
- SQLite (rusqlite) + FTS5 search
- ffmpeg + yt-dlp (sidecars in the container)
- Plain HTML/JS static UI
- Docker

## Quick start (local)

```sh
cargo run          # builds and boots the server on http://127.0.0.1:8080
```

Open http://127.0.0.1:8080 — the static UI (Library / Video / Playlist /
Admin tabs) should load. `/health` returns `ok`.

## Quick start (Docker)

```sh
# Mount your video folder(s) and a data folder, then:
docker compose up -d
```

The first request to http://localhost:8080 shows the setup wizard. See
[Deployment](#deployment) for the full story.

## Setup wizard

On first run (no `config.json`), the UI shows a setup wizard that collects:

- **Admin password** — stored hashed with argon2id; only the admin can use the
  Admin tab.
- **Watch directories** — folders to scan for videos (read-only on NASOMV).
- **Data directory** — where generated HLS segments, thumbnails, and the SQLite
  DB are written.
- **Scan interval** — seconds between re-scans (default 5).
- **Anonymous view** — whether non-authenticated users can browse/play videos.
- **YouTube download directory** — where yt-dlp downloads YouTube videos.

Completing the wizard writes `config.json` (with the argon2 hash) and creates
the SQLite schema. Until complete, all other routes return "not configured".

## Configuration

`config.json` (generated by the wizard; do not hand-edit the password hash):

| Field | Type | Description |
| --- | --- | --- |
| `port` | number | HTTP port (default 8080) |
| `watch_dirs` | array of strings | Folders to scan for videos |
| `youtube_download_dir` | string | Where yt-dlp downloads YouTube videos |
| `data_dir` | string | Where HLS, thumbnails, and the DB are written |
| `scan_interval_s` | number | Seconds between re-scans |
| `anonymous_view` | bool | Allow non-authenticated browse/play |
| `admin_password_hash` | string | argon2id hash (set by the wizard) |
| `version_check_url` | string | GitHub Releases check URL |
| `upnp` | object | Sonos/UPnP casting (see below) |

## API routes (axum 0.7)

Path parameters use axum 0.7 `:id` syntax, **not** the axum 0.8 `{id}` form.
A literal `{id}` segment never matches, so requests fall through to the
`/*path` static-file catch-all (which is always registered last).

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/api/videos` | List videos (optional `?q=` FTS search) |
| `POST`, `DELETE` | `/api/videos/:id` | Edit / delete a video (admin) |
| `GET`, `POST` | `/api/playlists` | List / create playlists (create is admin) |
| `GET`, `PUT`, `DELETE` | `/api/playlists/:id` | Playlist detail / rename / delete |
| `POST`, `DELETE` | `/api/playlists/:id/items` | Add / remove playlist items |
| `POST` | `/api/import` | YouTube import (admin) |
| `GET`, `POST` | `/api/settings` | Read / update settings (admin) |
| `GET` | `/api/version` | Version + update check (admin) |
| `GET` | `/health` | Liveness probe |
| `GET` | `/stream/*path` | HLS segments / playlists |
| `GET` | `/thumbnail/*path` | Video thumbnails |
| `POST` | `/admin/login` | Log in (sets HttpOnly session cookie) |
| `POST` | `/admin/logout` | Log out |
| `GET` | `/api/session` | `{"authenticated": bool}` |
| `GET` | `/api/speakers` | List discovered speakers (online status) |
| `POST` | `/api/cast/:video_id/:speaker_id` | Cast a pre-baked audio file to a speaker (admin, `{"volume": 0..100}`) |
| `GET` | `/audio/:id` | Serve a pre-baked direct audio file (`audio_path`) |

A regression test in `src/server.rs` asserts that `GET /api/videos/1` matches
the specific route (405 with `Allow: POST, DELETE`) rather than the catch-all.

## Deployment

`home-video` runs as a single Docker container. The image is multi-stage:
a `rust` builder stage compiles the binary, and a slim `debian` runtime stage
ships the binary plus `ffmpeg`, `yt-dlp`, and `ca-certificates`.

`compose.yml` mounts:

- `./watch` (read-only) — the folder(s) containing your videos.
- `./data` (read-write) — generated HLS, thumbnails, and the SQLite DB.
- `./config` (read-write) — `config.json` (the admin password hash).

The container listens on port 8080 internally; `compose.yml` maps it to
`${HOST_PORT:-8080}` on the host.

```sh
# On the NASOMV host (or any host with the folders present):
mkdir -p watch data config
docker compose up -d
```

Then open http://localhost:8080, complete the setup wizard, and drop videos
into `watch/`. They appear in the Library within the scan interval with a
thumbnail and a working HLS stream.

To update: run `scripts/deploy.sh` on the NAS, or equivalently `git pull &&
docker compose up -d --build`. The "update available" banner in the Admin
tab points at the GitHub Releases page.


## UPnP / Sonos casting (Phase 3)

Optional. `config.json` may include an `upnp` block:

```json
"upnp": {
  "enabled": true,
  "discovery_interval_s": 30,
  "server_ip": "192.168.1.42"
}
```

- `server_ip` — the LAN IP this server listens on (needed so the speaker can
  fetch the audio URI). If unset, the host is auto-detected; `127.0.0.1` or
  loopback are rejected loudly rather than guessed.
- `discovery_interval_s` — SSDP rescan interval.

Audio is pre-baked at ingest (`data/audio/<video_id>.m4a`, AAC 192k, stored as
`audio_path` in the DB). The web cast flow POSTs to `/api/cast/:video_id/:speaker_id`;
the CLI mirrors it:

```sh
home-video cast <videoId> <speakerId> [--volume N]
```

Requires `POST /api/cast/:video_id/:speaker_id` to be admin-authenticated (the
video + speaker ids are path parameters; the optional body is `{"volume": 0..100}`,
default 50).
